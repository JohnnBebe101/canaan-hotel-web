# PROJECT MASTER RULES: Legacy Conversion & System Expansion

## 1. UI/UX FIDELITY (The "85% to 100%" Polish)
- **Visual Accuracy**: When converting `our-services.html`, `about-us.html`, etc., to `.tsx`, you must maintain 1:1 visual parity. 
- **Tailwind Strategy**: Use the `tailwind.config.ts` for theme colors. Use arbitrary values (e.g., `top-[17%]`) only if the standard Tailwind scale fails to match the original CSS.
- **Next.js Patterns**: Use `next/image` for all assets and `next/link` for navigation.

## 2. NEW SYSTEM GENERATION (Admin, CRM, Dashboard)
- **Design DNA**: The Admin, CRM, and Dashboard pages must inherit the design language (colors, borders, shadows) found in the `index.html` and `about-us.html`.
- **Booking System**: Implement a clean, state-driven booking flow using React hooks. Ensure the UI matches the polished aesthetic of the landing pages.
- **CRM/Dashboard**: Use a consistent sidebar layout. Data tables and cards must use the same border-radius and shadow-depths defined in the UI polish phase.

## 3. TECHNICAL CONSTRAINTS
- **TypeScript**: No `any` type. Define strict Interfaces for all data objects (e.g., `Service`, `Booking`, `User`).
- **Context Management**: Keep components under 250 lines. Break UI into `/components/ui` (atomic) and `/components/features` (complex).
